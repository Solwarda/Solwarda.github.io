解码 AI 编码智能体的核心：Agent Loop

本文是 learn-claude-code 项目的第一次学习记录。整个项目通过 20 个由浅入深的示例，一步步揭示 Claude Code（Anthropic 的 AI 编码智能体）的内部机制。

一、开篇：一个疑问

Claude Code 能在终端里听懂你的自然语言需求，自主地执行 shell 命令、读写文件、调试代码、甚至提交 PR。这看起来像魔法。

但魔法背后是什么？

带着这个疑问，我打开了这个项目的第一课：s01_agent_loop。

项目地址：learn-claude-code（Anthropic 官方出品）

三、代码解剖：208 行的完整 Agent

s01_agent_loop/code.py 只有 208 行，却实现了一个完整可运行的 AI 编码智能体。我们来逐层拆解。

3.1 环境准备（第 30-55 行）

关键细节：

  • 通过 .env 文件加载配置，灵活切换 API 端点
  • System Prompt 只有一句话：“Use bash to solve tasks. Act, don’t explain.”——这正是 Claude Code 的简洁高效哲学
  • 注意一个巧妙的兼容处理（第 49-50 行）：当使用非官方端点时，移除 ANTHROPIC_AUTH_TOKEN，避免与自定义 base URL 冲突

值得一提的是代码中还包含了对 readline 的 macOS 兼容处理（第 32-42 行），专门修复了 libedit 在处理中文输入时的退格问题——这种细腻的细节遍布整个代码库。

3.2 工具定义（第 58-66 行）

智能体只有一个工具：bash。赋予 AI 执行 shell 命令的能力，就打开了无限可能——文件操作、代码运行、网络请求、Git 操作，全都可以通过命令行完成。

这就是”小工具，大作为”的设计理念。

3.3 工具执行与安全（第 70-82 行）

这段代码体现了几个重要的工程考量：

机制 目的
黑名单过滤 阻止 rm -rf /、sudo 等危险命令
120 秒超时 防止命令永久挂起
输出截断（50KB） 避免模型上下文被海量输出撑爆
返回错误而非抛异常 让 LLM 自己决定如何应对错误

最后一点尤其关键：AI 智能体的错误处理哲学不是”崩溃后重启”，而是”把错误信息喂回模型，让它自己修正”。

四、动手实验：和智能体对话

我启动程序后问了一个问题：

我： 当前目录下 code.py 有多少行代码，主要功能是什么？

AI 智能体的行为：

  1. 识别到需要执行命令 → 调用 bash 工具执行 wc -l code.py
  2. 工具返回 208 行 → 但 find 发现了更多 code.py 文件
  3. 进一步探索 → 再次调用 bash 查找所有文件
  4. 给出最终回答 → 总结代码行数及功能

整个过程完全自主完成，我只需要说一句话。

这就是 Agent Loop 的威力：人类给方向，AI 负责执行路径上的所有细节决策。

五、关键收获

维度 洞察
核心模式 Agent 的本质是一个 while 循环：LLM 调用 → 工具执行 → 结果回馈
工具是能力的边界 给 AI 什么工具，它就有什么能力。一个 bash 工具 = 无限可能
错误处理 不是 try-catch 隐藏错误，而是把错误给 LLM 让它自己修复
透明 > 黑盒 打印每一轮循环的细节，让开发者理解 AI 的决策过程
简洁的力量 208 行代码实现了一个完整可用的 Agent。复杂不等于强大
