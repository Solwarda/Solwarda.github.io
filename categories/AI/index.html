解码 AI 编码智能体的核心：Agent Loop

本文是 learn-claude-code 项目的第一次学习记录。整个项目通过 20 个由浅入深的示例，一步步揭示 Claude Code（Anthropic 的 AI 编码智能体）的内部机制。

一、开篇：一个疑问

Claude Code 能在终端里听懂你的自然语言需求，自主地执行 shell 命令、读写文件、调试代码、甚至提交 PR。这看起来像魔法。

但魔法背后是什么？

带着这个疑问，我打开了这个项目的第一课：s01_agent_loop。

项目地址：learn-claude-code（Anthropic 官方出品）

3.3 工具定义（第 57-67 行）

智能体只有一个工具：bash。注意这里比常见的最小示例多了一个 description 字段——它帮助模型理解工具的使用场景，提升工具选择的准确性。

赋予 AI 执行 shell 命令的能力，就打开了无限可能——文件操作、代码运行、网络请求、Git 操作，全都可以通过命令行完成。

这就是”小工具，大作为”的设计理念。

3.4 工具执行与安全（第 70-82 行）

这段代码体现了几个重要的工程考量：

机制 目的
黑名单过滤 阻止 rm -rf /、sudo 等危险命令
120 秒超时 防止命令永久挂起
输出截断（50000 字符） 避免模型上下文被海量输出撑爆
返回错误而非抛异常 让 LLM 自己决定如何应对错误
FileNotFoundError/OSError 捕获 处理命令不存在或系统调用失败的情况

最后两点尤其关键：AI 智能体的错误处理哲学不是”崩溃后重启”，而是”把错误信息喂回模型，让它自己修正”。 如果执行的命令不存在，模型收到错误信息后可以尝试替代方案。

3.6 交互界面（第 188-209 行）

一个简洁的 REPL（Read-Eval-Print Loop）界面，包含几个细致的设计：

  • \033[36m 和 \033[0m 是 ANSI 转义码，给提示符加上青色
  • try/except (EOFError, KeyboardInterrupt) 确保 Ctrl+D / Ctrl+C 能优雅退出
  • 每次对话保留完整 history，模型能”记住”之前的对话
  • agent_loop 返回后，代码从 history 中提取模型的最终文本回复并打印——注意这里用 getattr 安全地检查 block.type，因为 response.content 中的 block 是对象而非字典

五、关键收获

维度 洞察
核心模式 Agent 的本质是一个 while 循环：LLM 调用 → 工具执行 → 结果回馈
工具是能力的边界 给 AI 什么工具，它就有什么能力。一个 bash 工具 = 无限可能
错误处理 不是 try-catch 隐藏错误，而是把错误给 LLM 让它自己修复
透明 > 黑盒 打印每一轮循环的细节，让开发者理解 AI 的决策过程
简洁的力量 209 行代码实现了一个完整可用的 Agent。复杂不等于强大
